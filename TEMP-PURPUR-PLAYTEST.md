# Temporary Minecraft Java Purpur 1.21.11 playtest

- Main repo: huyfefe368-source/minecraft-actions (public, workflow code only).
- State repo: huyfefe368-source/minecraft-temporary-backups (PRIVATE, GitHub Release assets).
- Public Java 1.21.11 test address while runner is active: 160.191.51.148:25577.
- Existing VPS game gateways 25565 and 25575 are not changed.

## Starting and resuming
Choose Actions > Temp Purpur 1.21.11 - Interactive Development Playtest
> Run workflow > 20/60/120/180/240 minutes.

Each manually started job downloads the newest validated complete compressed
archive from the private GitHub Release (via the VPS as a secured proxy),
checks SHA-256, and restores the entire Minecraft directory.

The runner uses Java 21, 4 vCPU / 16 GB standard public runner,
with -Xms2G and -Xmx12G. Minecraft should show "SERVER READY" in Actions logs
before players connect.

At the end of the selected playtest it sends "save-all flush" then "stop",
waits for Java to exit, then archives EVERYTHING under the Minecraft server
directory using tar/zstd. The VPS validates the archive and publishes it to the
private GitHub release along with a SHA-256 manifest.

There is no 24/7 runner loop and no automated dispatch of new jobs.
Github Actions service terms limit usage to development and testing of
the repository's project. The job may be interrupted or fail early.

## Migration onto the paid host
Open the private GitHub repository's "Purpur 1.21.11 - Complete Server Snapshots"
release, choose the newest state archive with a matching manifest JSON.
Download it and validate the SHA256 field in the manifest.
Extract all files into the paid host server root; this includes:
- all three world dimensions and level/player data
- Purpur server.jar, plugin jars and plugin data
- bukkit/paper/spigot/purpur settings, server.properties, eula.txt
- logs, whitelists/bans/ops, and any extra files generated by the server

Change server-ip from 127.0.0.1 to blank or the paid host's configured bind address,
and use the new port required by that host. Keep online-mode=true.
Use Java 21 and verify the hosted server before deleting these temporary backups.

## Limits and backups
GitHub Release limits individual assets to under 2 GiB, so this workflow will
refuse oversized archives rather than silently upload incomplete snapshots.
If the job is killed abruptly, final cleanup might not complete.
Preserve a separate backup before upgrading plugins or Minecraft versions.
